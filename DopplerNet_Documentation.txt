1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
DopplerNet is a sophisticated acoustic simulation platform designed to generate
highly realistic, physics-grounded audio for vehicles and drones. It is primarily
used for creating datasets for machine learning models that need to recognize
trajectories, speeds, and distances from audio signals.

The simulator goes beyond simple pitch-shifting; it uses time-domain resampling
to maintain phase consistency and realistic frequency sweeps, accounts for 
atmospheric conditions (temperature, humidity), and simulates complex spatial
paths like parabolas and Bezier curves.

2. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
The project is built as a Flask web application with a clear separation of 
concerns:
- Core: Configuration and persistence logic.
- Physics: Pure mathematical models of vehicle motion.
- Audio: Signal processing and mixing.
- Visualization: Path plotting and data analysis.
- Routes: API endpoints that connect the UI to the backend logic.
- Utilities: Automated testing, map extraction, and audio preprocessing.

3. FILE-BY-FILE BREAKDOWN
--------------------------------------------------------------------------------

A. ROOT DIRECTORY (Server & Entry Points)
-----------------------------------------
- app_batch.py: 
  The main entry point. Initializes the Flask app, registers Blueprints, and 
  serves static map extraction assets. It acts as the gateway for the frontend.

- requirements.txt: 
  Lists dependencies: numpy, scipy, librosa, soundfile, matplotlib, flask, 
  flask-cors, and opencv-python (for map extraction).

- seamless_audio_generate.py: 
  A preprocessing utility. It converts raw MP3 vehicle captures into stitched, 
  mono WAV files, trimming silences to ensure a continuous "engine hum" source.

- reproduce_bug.py: 
  A diagnostic script used to validate and fix a historical bug in the Doppler 
  resampling engine regarding output buffer lengths.

B. /core/ (System Logic)
------------------------
- core/config.py: 
  Central source of truth for directory paths and default randomization ranges 
  (speed: 15-50 m/s, distance: 5-1000m, etc.). Sets CPU thread limits.

- core/progress.py: 
  Manages `generation_progress.json` to provide real-time batch status updates.

- core/sampler.py: 
  Implements the `CyclicIntegerSampler`. It uses Number Theory (coprime steps) 
  to ensure that a batch covers an entire parameter range (e.g., every 
  integer speed from 15 to 50) in a shuffled, non-sequential order.

C. /audio/ (Signal Processing)
------------------------------
- audio/audio_utils.py: 
  The signal processing engine.
  - Atmosphere: c = 331.3 * sqrt(1 + T/273.15) + humidity_factor.
  - Resampling: The `apply_true_doppler_shift` function calculates the discrete 
    integral of the frequency ratio to determine the exact index to read 
    from the source audio for every single output sample (SR=44100Hz).
  - Stereo: `save_stereo_audio` stacks two separately calculated mono tracks.

- audio/generation.py: 
  Orchestrates the creation of a clip. It samples parameters, calls the 
  physics engine, applies Doppler, and generates `.npy` ML features:
  - frequency.npy: Normalized dominant frequency track.
  - dfdt.npy: Normalized rate of change of frequency ($dF/dt$).
  - rms.npy: Frame-by-frame energy envelope.
  - spec_topk.npy: Tracks top-3 loudest frequency components.

D. /physics/ (Mathematical Models)
----------------------------------
- physics/straight_line.py: 
  Computes the classic perpendicular pass-by geometry.
- physics/parabola.py: 
  Models $y = ax^2 + h$. Uses arc-length considerations to normalize speed.
- physics/bezier.py: 
  Models Cubic Bezier curves. Useful for complex "S-curve" or turn simulations.
- physics/intersection.py: 
  Multi-vehicle logic for 4-way junctions, based on "Arrival Time" at (0,0).
- physics/map_trajectory.py: 
  Interpolates motion along a custom pixel-map path at a target average speed.

E. /visualization/ (Graphics and QA)
------------------------------------
- visualization/plot_utils.py: 
  Generates PNGs of the overhead scene (Observer "x", vehicle path, start/end).
- visualization/validation.py: 
  Checks if simulated paths in the "Busy Road" mode cross the median or 
  leave the road boundaries.
- visualization/graphs.py: 
  Post-batch analysis script. Generates histograms and correlation matrices 
  of a generated dataset to check for selection bias or distribution skew.

F. /routes/ (API Controllers)
-----------------------------
- routes/vehicle_routes.py: 
  Library management (Upload/Delete/Analyze).
- routes/batch_routes.py: 
  The core of the "Batch" engine. Handles random generation, busy road 
  overlaps, and the Map Extraction integration.
- routes/simulate_routes.py: 
  Controller for the "Interactive" tabs (Single/Dual Mic/Intersection).

G. /MapExtraction/ (Computer Vision)
------------------------------------
- MapExtraction/outline_to_json.py: 
  Uses `OpenCV` and `skeletonize` to convert hand-drawn road outlines into 
  mathematical point-lists that the `physics/` engine can follow.

H. /tests/ & Automation
-----------------------
- generate_screenshot.js: 
  Uses `Puppeteer` to launch a headless browser, "click" buttons in the UI, 
  perform a simulation, and save a screenshot for documentation/testing.

4. PHYSICS AND MATH CORE
--------------------------------------------------------------------------------

A. DOPPLER EQUATION
   $f_{obs} = f_{src} \cdot (c / (c - v_{radial}))$
   $v_{radial}$ is the dot product of the velocity vector and the relative 
   position unit vector.

B. ATTENUATION (1/R LAW)
   The project uses a Near-Field-Safe amplitude model:
   $A(t) = 1.0 / \sqrt{distance(t)^2 + 2.0^2}$
   This prevents "infinite volume" when a vehicle distance approaches zero.

C. KINEMATIC CONSISTENCY
   For non-linear paths (Parabola, Bezier), the engine calculates the path's 
   derivative ($dB/d\tau$) and rescales the time-mapping to ensure the 
   resultant velocity magnitude matches the requested physical speed in m/s.
